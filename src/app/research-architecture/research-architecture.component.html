01Your questionBrowser · conversation context+

Think is selected by default. You can switch to Flash for direct answers or Goblin for the experimental base-model continuation. The browser sends the current conversation with your signed-in request. A chat session lives in browser memory; it is not persistent personal memory or a model learning new weights.

That familiar interface is built on existing model and runtime components. “From first principles” means understanding and rebuilding the stack around them, with each decision made visible.

Understand the model choice →
02Check access and limitsGoogle sign-in · gateway · shared quotas+

Amazon Cognito handles sign-in. API Gateway checks the access token and throttles traffic. The gateway validates the request and checks per-user and shared allowances in DynamoDB before invoking a private model worker.

The preview allows up to 20 requests per user and 100 shared requests per UTC day, with minute limits too. Shared limits still apply across accounts. Each model worker allows one concurrent request. These bound access; they are not a guarantee of a fixed AWS bill.

03Inspect the inputText integrity · before tools and inference+

The worker runs llm-input-hardening before preparing a tool call or model prompt. It checks for hidden controls, misleading Unicode and encoded obfuscation. An unavailable check stops the request.

Passing this check does not make text trustworthy. Ordinary readable text can still contain malicious instructions, and retrieved pages cross their own trust boundary.

04Choose the answer pathBounded calculator · source lookup · direct generation+

For the Qwen assistant, explicit rules choose one bounded tool step. Simple arithmetic uses a decimal calculator. Questions about this site’s owner use a maintained profile. Those answers skip the model entirely. Goblin takes the base-model continuation path.

Recognized factual questions check selected, indexed pages first, then whole-web search through a private SearXNG worker. Only the current question goes to search. If no evidence is available, the system declines to guess. Other questions proceed directly to generation.

The interface shows tool activity as the service starts and completes a calculator, lookup or profile operation. Those events describe real execution. This is rule-based routing, not an ensemble of specialist models.

05Generate, when neededQwen3.5-0.8B · llama.cpp · CPU Lambda+

Both assistant modes use the same Qwen checkpoint, quantized to Q8_0, in separate 4 GB ARM64 Lambda workers. Goblin has its own 4 GB CPU worker and PyTorch runtime. Weights load on demand. The prompt must fit a bounded context, and output has token, time and repetition limits.

Think has a reasoning budget for ordinary generation. Search-backed answers use direct generation in both modes: the model receives untrusted excerpts as context and produces a short answer. The interface adds the source links separately.

06Stream and measureAnswer deltas · token usage · completion receipt+

Server-sent events carry output through the gateway. “Thinking…” stays visible until the first answer text arrives, then the interface displays real answer chunks immediately. It is a waiting indicator, not a measurement of the model’s internal reasoning.

The browser measures first output, first answer and completion separately. The worker reports its cold or warm state and engine token usage; tool-only answers finish with an unknown model state. Response time and token usage appear beside completed answers, with the measurement method documented here.

The gateway records metadata-only totals before sending completion. The chat’s cost comparison uses an assumed frontier API rate of US$3 per million input tokens and US$15 per million output tokens, minus measured model-worker compute. It starts when tracking begins and excludes gateway, search, storage and other unmeasured costs. It is an approximate model-compute comparison, not net service savings or a claim of equal quality.

ALONGSIDE THE REQUEST

Observe first. Learn from evidence.

LangWatch records performance and outcomes. Conversation capture is off by default. If you opt in, messages and answers are redacted and saved to LangWatch and a private research archive for review. They are not automatically approved for training. Redaction is imperfect; avoid sharing sensitive information.

These records are observations, not proof of answer quality. Small diagnostic probes already catch failures; a broader held-out evaluation suite is still work to do.
