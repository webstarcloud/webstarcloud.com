01Your questionBrowser · conversation context+

Think is selected by default. You can switch to Flash for direct answers or Goblin for the experimental base-model continuation. The browser sends the current conversation with your signed-in request. A chat session lives in browser memory; it is not persistent personal memory or a model learning new weights.

That familiar interface is built on existing model and runtime components. “From first principles” means understanding and rebuilding the stack around them, with each decision made visible.

Understand the model choice →
02Check access and limitsGoogle sign-in · gateway · shared quotas+

Amazon Cognito handles sign-in. API Gateway checks the access token and throttles traffic. The gateway validates the request and checks per-user and shared allowances in DynamoDB before invoking a private model worker.

The preview allows up to 20 requests per user and 100 shared requests per UTC day, with minute limits too. Shared limits still apply across accounts. Each model worker allows one concurrent request. These bound access; they are not a guarantee of a fixed AWS bill.

03Inspect the inputText integrity · before tools and inference+

The worker runs llm-input-hardening before preparing a tool call or model prompt. It checks for hidden controls, misleading Unicode and encoded obfuscation. An unavailable check stops the request.

Passing this check does not make text trustworthy. Ordinary readable text can still contain malicious instructions, and retrieved pages cross their own trust boundary.

04Choose the answer pathCalculator · sources · optional memory and Python+

For the Qwen assistant, explicit rules enforce bounded tool operations. Jev, a small decision model from TypeSafe, helps classify the latest protected question when a semantic routing decision is useful. Its typed output is a suggestion; server rules still control the permitted route. It does not authorize actions or generate code. Simple arithmetic and recognized constant-power energy conversions use a decimal calculator. Explicit calculations, memory management and Python requests run in a 512 MB worker that cannot load a model. Questions about this site’s owner use a maintained profile. Those answers skip inference. Goblin takes the base-model continuation path.

Recognized factual questions check selected, indexed pages first, then whole-web search through a private SearXNG worker. Indexed snapshots must be no more than seven days old; lexical relevance checks reject some unrelated excerpts. Checked public excerpts can be reused for 60 seconds within a warm worker. This cache excludes recognized personal queries and never stores memories or answers. Neither a recent snapshot nor matching words proves a fact is correct.

Jev also ranks bounded public excerpts for relevance to the question. This is a second opinion on retrieved evidence, not a security boundary. Accepted excerpts remain untrusted data. The latest protected question and relevant public excerpts can reach TypeSafe; saved personal-memory text and earlier conversation are excluded from these decision calls.

Personal memory and Python are separate, optional tools. Mem0 stores only explicit Remember: notes under your verified account. Clear personal-recall questions retrieve up to three relevant notes; ordinary public questions skip memory. You can inspect and delete saved notes. Retrieved notes are untrusted historical data; memory does not train the model.

Run Python: executes code you supply in a fresh E2B sandbox with internet access disabled, a 10-second execution limit and a 30-second lifetime. After sign-in, “Agree and continue” enables these tools and research recording together. You can instead continue with optional features off, or change each setting later. Shared free-credit limits still apply. The assistant does not automatically write memories or generate code to execute.

The interface shows tool activity as the service starts and completes an operation, including intent routing, source ranking and answer support checks. Those events describe real execution. A completed decision check means it ran; it does not certify the answer’s truth.

Review repository: https://github.com/owner/repo, optionally followed by : focus, reads a pinned public revision and up to two source excerpts. Private repositories and other hosts are unsupported; repository code is never executed. The original Review the website repository command still works. Structural checks produce observations; the existing Qwen worker selects their IDs. It gets only the latest instruction and those observations. An invalid selection permits one repair, with at most two 128-token calls inside 75 seconds. A shared allowance permits three inspections daily. The result is partial, does not run tests and cannot change the repository. Why freeform bug review failed →

Retrieval changes the trust boundary →
05Generate, when neededQwen3.5-0.8B · llama.cpp · CPU Lambda+

Both assistant modes use the same Qwen checkpoint, quantized to Q8_0, in separate 4 GB ARM64 Lambda workers. Goblin has its own 4 GB CPU worker and PyTorch runtime. Weights load on demand. The prompt must fit a bounded context, and output has token, time and repetition limits.

Think has a reasoning budget for ordinary generation. Search-backed answers use direct generation in both modes: the model receives only the latest protected question and untrusted public excerpts, then produces a short draft. Earlier conversation and saved personal-memory text are excluded from this path. Before that draft reaches the browser, Jev checks whether the public excerpts support it. An unsupported or insufficiently supported draft becomes a fixed abstention. The check assesses support from the supplied sources, not whether those sources are true. The interface adds source links separately.

06Stream and measureAnswer deltas · token usage · completion receipt+

Server-sent events carry output through the gateway. “Thinking…” stays visible until the first answer text arrives, then the interface displays real answer chunks immediately. Source-backed drafts are buffered while their support is checked, so first-answer latency includes that check. It is a waiting indicator, not a measurement of the model’s internal reasoning.

The browser measures first output, first answer and completion separately. The worker reports its cold or warm state and engine token usage; tool-only answers finish with an unknown model state. Native token counts and decode rate describe the generated draft, including when the displayed response is an abstention. They do not measure how quickly buffered chunks reach the browser. Response time and token usage appear beside completed answers, with the measurement method documented here.

The gateway records metadata-only totals before sending completion. The chat’s cost comparison uses an assumed frontier API rate of US$3 per million input tokens and US$15 per million output tokens, minus measured model-worker compute. It starts when tracking begins and excludes gateway, search, TypeSafe decision API fees, storage and other unmeasured costs. It is an approximate model-compute comparison, not net service savings or a claim of equal quality.

ALONGSIDE THE REQUEST

Observe first. Learn from evidence.

LangWatch records performance and outcomes. The notice after sign-in asks you to choose before sending. “Agree and continue” enables personal memory, Python and research recording; the alternative keeps all three off. Recording can include messages, answers and retrieved notes in LangWatch and a private research archive for review. Memory inspection and deletion exchanges are excluded. Records are not automatically approved for training. Redaction is imperfect; avoid sharing sensitive information.

Your choices remain editable and follow your signed-in account across chats and navigation during this visit. They reset on sign-out, account switch or reload; sign-out and account changes also clear browser chat history. Turning recording off stops new captures and does not delete previous records. Input protection, automatic search and Jev’s decision stages work independently of these optional settings.

These records are observations, not proof of answer quality. Small diagnostic probes already catch failures; a broader held-out evaluation suite is still work to do.
